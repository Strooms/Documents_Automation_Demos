# Portfolio: document automation demos

> **Demo projects with synthetic data. Not client work.**
> Every document, name, number and company in this repository was generated by the code in it.
> Nothing here represents a client engagement, and no accuracy figure below comes from real-world data.

**Raditya Yoga Kurniawan** — freelancer (Upwork) working on AI-assisted document automation:
OCR and PDF data extraction, turning messy documents into clean spreadsheets/CSV/JSON, and
lightweight data analytics. These three small projects are practice builds that show how I approach
those problems: extract, validate the numbers, and be explicit about what the tool cannot do.

| Project | What it demonstrates | Verified by running |
|---|---|---|
| [`invoice-pdf-extractor`](invoice-pdf-extractor/) | Invoice PDFs in 4 layouts (incl. an image-only scan via Tesseract OCR) → JSON/CSV, with arithmetic validation that flags bad totals | 17 tests pass; 36/36 field checks on 4 synthetic files |
| [`bank-statement-parser`](bank-statement-parser/) | Two bank-statement layouts → one Sheets-ready CSV, with running-balance reconciliation that catches a tampered amount | 6 tests pass; 60/60 synthetic transactions parsed exactly |
| [`doc-qa-rag-mini`](doc-qa-rag-mini/) | Local (no API) retrieval Q&A over 10 documents with citations and a "not found" fallback | 7 tests pass; **7/10** test questions answered correctly — the 3 failures are documented |

## Quick start

Python 3.10+ (developed on 3.13). Each project is self-contained:

```bash
cd invoice-pdf-extractor        # or bank-statement-parser / doc-qa-rag-mini
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m pytest -q
```

See each project's README for the run commands, sample output and limitations. The invoice project's
OCR path needs the Tesseract binary (`sudo apt-get install tesseract-ocr`).

## Honest notes

- The extraction rules were developed against the same synthetic files they are scored on, so the numbers
  show "the pipeline works end to end", not how it would perform on your documents.
- Real documents are messier. I would start any real job by testing on a handful of your actual files and reporting the measured result.
